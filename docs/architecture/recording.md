# NexaVoice Call Recording & AI Transcription Architecture

## Overview
Recording in NexaVoice is designed with strict multi-party compliance, visual accessibility indicators, and AI transcription with speaker diarization.

## Recording Lifecycle
```
REQUESTED -> STARTING -> RECORDING <-> PAUSED -> STOPPING -> COMPLETED
                                                           -> FAILED
                                                           -> DELETED
```

## Security & Multi-party Consent
- **Model: `RecordingConsent`**:
  - Automatically created for every participant in the call upon recording initiation.
  - Initial state: `GRANTED` for the recording initiator, `PENDING` for all other participants.
  - Participants receive a modal/banner prompt to submit or decline consent (`submitRecordingConsent`).
- **Visual Accessibility**:
  - Live status MUST feature clear text indicators (`RECORDING IN PROGRESS` / `RECORDING PAUSED`) to comply with accessibility standards, preventing reliance solely on red/yellow color cues.
- **Signed Time-Limited Playback URLs**:
  - Playback tokens are short-lived HMAC-signed tokens generated by `getRecordingPlaybackUrl`.
  - IDOR protection ensures only authorized call participants or designated compliance roles can generate playback URLs.

## AI Transcription & Speaker Diarization
- **Interface: `TranscriptionProvider`**:
  - `DefaultTranscriptionProvider` performs asynchronous diarization parsing, mapping participant timestamps to `TranscriptSegment` entities.
  - `CallTranscript` stores full text, language, status, and associated segment arrays.
